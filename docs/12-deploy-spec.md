# 公開（デプロイ）仕様

作成: 2026/08/30 ／ 更新: 2026/09/09 ／ 東田
用途: **Claude Code に渡して実装させる。**サイトを公開できる状態にするまで。
前提: UIはできている。データは `10-sync-spec.md` の `npm run sync` で `circles.json` が生成される。

---

## 0. 結論から

**Next.js（App Router）＋ Vercel の静的生成。**サーバーは持たない。データベースも今は要らない。

158団体、更新は年1回、書き込むのは1人。ビルド時に `circles.json` を読んで158枚のHTMLを吐けば終わる。**リクエストのたびに動くものが何もないので、落ちない・遅くならない・金がかからない。**

「これから増やしていく」規模を先回りしても、増えるのは団体数（158→200程度）で、これは静的生成にとって何の負荷でもない。**構成を変える必要が出るのは団体数ではなく、団体自身に編集させ始めるとき**（§8）。

## 1. リポジトリ構成

```
/app
  page.tsx                 一覧（S-01）
  c/[id]/page.tsx          団体ページ（S-02）＋団体ごとのOGPメタデータ
  not-found.tsx
  robots.ts
  sitemap.ts
/components
/data
  circles.json             ← sync が生成。手で直さない
/public/photos             ← 手元で変換して配置。syncは走査のみ。gitに含める
/scripts
  sync.ts                  10-sync-spec.md の実装
  draft.ts
```

**`circles.json` と `/public/photos` はリポジトリにコミットする。**外部から取りに行かない。ビルドがネットワークに依存しなくなるし、いつのデータで公開されたかがgitの履歴に残る。

## 3. データの読み込み

データの流れは次のとおり。

```
Googleフォーム（取材者が入力）
   ↓
回答 タブ
   ↓ VLOOKUP
掲載データ タブ ─┐
団体マスタ K列「大分類」 ─┼─ npm run sync → data/circles.json
public/photos（変換済み） ─┘                 （写真は走査のみ）
                                                ↓ build時にimport
                                      一覧＋団体ページを静的生成
```

syncは `掲載データ` タブを本体として読み、`division` だけは `団体マスタ` のK列 `大分類` から読む。`circles.json` はビルド時に `import` するだけで、画面からfetchしない。

型は `/types/circle.ts` に定義する。`data/circles.sample.json` も同じ形にし、ダミーと本番を差し替えるだけで動く状態を保つ。

### 3-1. 男女比の丸め

JSONには `male_ratio` として男子の割合（0〜100）が入る。**表示のときに合計10へ丸める。**共通関数 `genderRatio()` にする。

- 合計が10になるように丸める
- 1%でもあれば0にしない。1%は `1 : 9`、99%は `9 : 1`
- 0%は `女子のみ`、100%は `男子のみ` の文字列を返す
- `male_ratio` が `null` なら `—`

この関数は一覧と詳細の両方から呼ぶ。片方だけ実装しない。

## 4. 画像

syncは画像を変換しない。手元で変換したファイルを `/public/photos` に置き、syncはファイル名を走査して `icon` と `photos` を組み立てる。**変換済みなので `next/image` の最適化は使わない**（`unoptimized`）。

- アイコン: `{id}-icon.webp`。1:1・幅400の1枚だけで、`@600` は作らない
- ヒーロー写真: `{id}-{n}.webp`（3:2・幅1200）と `{id}-{n}@600.webp`（幅600）。最大3枚
- 一覧タイル: `photos[0]`、なければ `icon`。両方なければジャンル色と頭文字
- ヒーロー: `photos` を最大3枚。photosがなくiconだけならiconを使う
- OGP: photosが1枚でもあれば `photos[0]`（1200×800）。photosがなくiconだけならicon（400×400）
- `<img>` の `width` / `height` を必ず指定する。指定しないとスクロール中に画面が飛ぶ

## 5. 公開と、確認用のプレビュー ★ここが要点

団体に「公開前に確認してもらう」と約束しているので、**まだ公開していない団体を見せるURL**が要る。

**ブランチで分ける。**

**2026-09-24 改訂:** 環境（ブランチ）で含める団体を変えるのをやめ、団体ごとの扱いにした。

| 公開可否 | 一覧 | `/c/{id}` | 見え方 |
|---|---|---|---|
| `OK`（原稿あり） | 出す | 出す | 通常公開 |
| 空欄・`確認中` | 出さない | 出す（URL を直接開いたときだけ） | `noindex, nofollow`、上部に `ink` 地で `掲載前の確認用ページです` |
| `NG`・`非公開` など | 出さない | 出さない（ビルドに含めない） | — |

- 確認用ページは `ALLOW_INDEXING` に関わらず常に `robots: noindex, nofollow`。**検索に載ったら約束違反になる**
- サイトマップは作っていない。作るときは確認用ページを含めない
- 団体に送るURLは `https://〇〇.vercel.app/c/c042` の形

OKが出たら `掲載データ` の `公開可否` を `OK` にして、`main` にマージすれば本番に出る。

## 6. ドメインとOGP

**ドメインを取る。**`.vercel.app` のURLを団体に送ると、それだけで信用が2割落ちる。年1,500円程度の投資で、面談の説得力が変わる。

**OGPは団体ごとに出す。**リンクはInstagramのDMで共有されるので、カードの見え方がそのままクリック率になる。

- 団体ページのmetadataから画像を指定する
- `photos` が1枚でもあれば `photos[0]` を1200×800として指定する
- `photos` がなく `icon` だけなら、iconを400×400として指定する
- どちらもなければ団体固有の画像は指定しない
- `title` は `団体名 | 京産大サークル名鑑`、`description` はキャッチコピー

`sitemap.ts` で全団体ページを列挙する。

## 7. 公開前チェック

1. 本番ビルドに `確認中` の団体が1件も混ざっていないか（**ビルドログに件数を出す**）
2. `robots.txt` は常に `allow`。索引の可否は meta の `noindex` と `ALLOW_INDEXING` で制御する
   （クロールを止めると meta の `noindex` を読ませられず、外部リンク経由でURLだけが検索結果に載ることがあるため）
3. 404ページが機能しているか
4. OGPをカードデバッガで確認（実際にDMに貼って見る）
5. 375px幅で横スクロールが出ないか
6. 写真0枚の団体、未確認だらけの団体で崩れないか
7. Lighthouse のパフォーマンスが90以上（静的生成なので出るはず。出ないなら画像のサイズ指定漏れ）

## 8. いつ構成を変えるか ★先に決めておく

**団体数では変えない。**500団体でも静的生成で足りる。

変えるのは次のどれかが起きたとき。

| きっかけ | 移行先 |
|---|---|
| **団体自身に編集させる** | Supabase（認証＋RLS）。これが本命の分岐点 |
| 更新が月1回以上になる | Supabase または CMS |
| 「気になる」を端末をまたいで残したい | Supabase |
| 閲覧数を団体ごとに見せたい | ログ基盤 |

いまは全部「まだ」。**先に作ると、ログイン・権限・監査の実装が丸ごと増えて、面談が止まる。**

移行するときも `circles.json` の形は変えない。**データの出どころが変わるだけで、画面は一切触らない**設計にしておく。

## 9. 運用コマンド

```bash
npm run sync        # 掲載データ＋団体マスタ＋写真走査 → circles.json
npm run dev         # ローカル確認
npm run build       # 本番ビルド（公開対象の件数をログに出す）
git add -A && git commit -m "sync 2026-09-14" && git push
```

`sync` は生成まで。**コミットは自分でやる。**何が変わったかgit diffで見てから公開する。自動コミットにすると、意図しない団体が公開される事故が起きる。
