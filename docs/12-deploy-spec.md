# 公開（デプロイ）仕様

作成: 2026/08/30 ／ 東田
用途: **Claude Code に渡して実装させる。**サイトを公開できる状態にするまで。
前提: UIはできている。データは `10-sync-spec.md` の `npm run sync` で `circles.json` が生成される。

---

## 0. 結論から

**Next.js（App Router）＋ Vercel の静的生成。**サーバーは持たない。データベースも今は要らない。

158団体、更新は年1回、書き込むのは1人。ビルド時に `circles.json` を読んで158枚のHTMLを吐けば終わる。**リクエストのたびに動くものが何もないので、落ちない・遅くならない・金がかからない。**

「これから増やしていく」規模を先回りしても、増えるのは団体数（158→200程度）で、これは静的生成にとって何の負荷でもない。**構成を変える必要が出るのは団体数ではなく、団体自身に編集させ始めるとき**（§8）。

## 1. リポジトリ構成

```
/app
  page.tsx                 一覧（S-01）
  c/[id]/page.tsx          団体ページ（S-02）
  opengraph-image.tsx      OGP画像（団体ごと）
  not-found.tsx
  robots.ts
  sitemap.ts
/components
/data
  circles.json             ← sync が生成。手で直さない
  .image-cache.json        （gitignore）
/public/photos             ← sync が生成。gitに含める
/scripts
  sync.ts                  10-sync-spec.md の実装
  draft.ts
```

**`circles.json` と `/public/photos` はリポジトリにコミットする。**外部から取りに行かない。ビルドがネットワークに依存しなくなるし、いつのデータで公開されたかがgitの履歴に残る。

## 2. ルーティング

| パス | 中身 |
|---|---|
| `/` | 一覧（S-01） |
| `/c/[id]` | 団体ページ。`id` は `c001` 形式 |

`generateStaticParams` で公開対象の全IDを返す。**完全な静的生成。**ISRもSSRも使わない。

存在しないIDは404。

## 3. データの読み込み

`circles.json` をビルド時に `import` するだけ。fetchしない。

型は `/types/circle.ts` に定義して、`04-dummy-data.json` と同じ形にする。**ダミーと本番を差し替えるだけで動く状態を保つ。**

### 3-1. 男女比の丸め

JSONには実数（`{male, female}`）が入っている。**表示のときに合計10へ丸める。**共通関数にする。

- 合計が10になるよう調整（四捨五入で9や11になったら人数の多い側で吸収）
- **1人でもいれば0にしない。**56人中2人でも `9 : 1`
- 本当に0人なら `女子のみ` / `男子のみ` の文字列を返す
- `gender` が `null` なら `—`

この関数は一覧と詳細の両方から呼ぶ。片方だけ実装しない。

## 4. 画像

`sync` が `/public/photos` に `c001-1.webp`（幅1200）と `c001-1@600.webp` を出している。**変換済みなので `next/image` の最適化は使わない**（`unoptimized`）。二重に処理する意味がない。

- ヒーロー: 1200を使う。1枚目だけ `priority`、2枚目以降は遅延
- 一覧のサムネ: `@600` を使う
- `width` / `height` を必ず指定する（3:2固定なので `1200 / 800`）。**指定しないとスクロール中に画面が飛ぶ**

## 5. 公開と、確認用のプレビュー ★ここが要点

団体に「公開前に確認してもらう」と約束しているので、**まだ公開していない団体を見せるURL**が要る。

**ブランチで分ける。**

| 環境 | ブランチ | 含める団体 | 見え方 |
|---|---|---|---|
| 本番 | `main` | `公開してよいか = OK` のみ | 通常公開 |
| 確認用 | `preview` | `OK` ＋ `確認中` | `noindex`、全ページ上部に確認用バーを出す |

- 環境変数 `INCLUDE_UNCONFIRMED=1` のときだけ `確認中` を含める。Vercel の `preview` ブランチにこれを設定する
- 確認用ビルドでは `robots: noindex, nofollow` を必ず返す。**検索に載ったら約束違反になる**
- 確認用の全ページ上部に、`ink` 地のバーを固定で出す: `これは掲載前の確認用ページです。まだ公開されていません。`
- 団体に送るURLは `https://preview-〇〇.vercel.app/c/c042` の形

OKが出たらシートの `公開してよいか` を `OK` にして、`main` にマージすれば本番に出る。

## 6. ドメインとOGP

**ドメインを取る。**`.vercel.app` のURLを団体に送ると、それだけで信用が2割落ちる。年1,500円程度の投資で、面談の説得力が変わる。

**OGPは団体ごとに出す。**リンクはInstagramのDMで共有されるので、カードの見え方がそのままクリック率になる。

- `opengraph-image.tsx` で1200×630を生成
- 写真がある団体は1枚目を敷いて、暗幕＋団体名を白で重ねる（ヒーローと同じ組み方）
- 写真がない団体はジャンル色ベタ塗りに団体名
- `title` は `団体名 | 京産大サークル名鑑`、`description` はキャッチコピー

`sitemap.ts` で全団体ページを列挙する。

## 7. 公開前チェック

1. 本番ビルドに `確認中` の団体が1件も混ざっていないか（**ビルドログに件数を出す**）
2. `robots.txt` は常に `allow`。索引の可否は meta の `noindex` と `ALLOW_INDEXING` で制御する
   （クロールを止めると meta の `noindex` を読ませられず、外部リンク経由でURLだけが検索結果に載ることがあるため）
3. 404ページが機能しているか
4. OGPをカードデバッガで確認（実際にDMに貼って見る）
5. 375px幅で横スクロールが出ないか
6. 写真0枚の団体、未確認だらけの団体で崩れないか
7. Lighthouse のパフォーマンスが90以上（静的生成なので出るはず。出ないなら画像のサイズ指定漏れ）

## 8. いつ構成を変えるか ★先に決めておく

**団体数では変えない。**500団体でも静的生成で足りる。

変えるのは次のどれかが起きたとき。

| きっかけ | 移行先 |
|---|---|
| **団体自身に編集させる** | Supabase（認証＋RLS）。これが本命の分岐点 |
| 更新が月1回以上になる | Supabase または CMS |
| 「気になる」を端末をまたいで残したい | Supabase |
| 閲覧数を団体ごとに見せたい | ログ基盤 |

いまは全部「まだ」。**先に作ると、ログイン・権限・監査の実装が丸ごと増えて、面談が止まる。**

移行するときも `circles.json` の形は変えない。**データの出どころが変わるだけで、画面は一切触らない**設計にしておく。

## 9. 運用コマンド

```bash
npm run sync        # シート＋写真 → circles.json + /public/photos
npm run dev         # ローカル確認
npm run build       # 本番ビルド（公開対象の件数をログに出す）
git add -A && git commit -m "sync 2026-09-14" && git push
```

`sync` は生成まで。**コミットは自分でやる。**何が変わったかgit diffで見てから公開する。自動コミットにすると、意図しない団体が公開される事故が起きる。
