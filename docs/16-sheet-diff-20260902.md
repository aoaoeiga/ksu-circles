## 1. 9/2版の構成

3タブ。**`掲載データ` は手で埋める台帳ではなく、`回答` からの VLOOKUP 派生ビュー**（159行が式で埋めてある）。

| `回答` | ヘッダのみ（**0件**） | フォームの回答。35問 |
| `団体マスタ` | 158 | 団体ID・団体名・区分・ジャンル・担当・優先度・アタック方法・進捗・面談日・備考 |
| `掲載データ` | 158 | 47列 = 団体ID 1列 ＋ `回答` からの式 40列 ＋ 手入力 6列 |

### 式で解決している3か所（ここは前進している）

```
曜日        月〜日の7列 = REGEXMATCH(活動曜日, "月") … の真偽値
曜日未確認  活動曜日が空 → TRUE / "決まっていない"を含む → TRUE
年会費表示  年会費状況="無料（0円）" → "¥0/年"
            年会費状況="未確認"     → "未確認"
            金額が空               → "未確認"
            それ以外               → "¥{金額}/年"
写真        Drive URL から ID を抜いて
            https://drive.google.com/thumbnail?id={id}&sz=w1600 に変換
```

曜日の正規化と `¥0` / 未確認の区別は、**シート側で解けている。**旧フォームで壊れていた原因の一部はここで消える。

## 4. `scripts/sync.ts` との食い違い

- sync は `SHEET_NAME` の**1タブだけ**を読む。新構成では `掲載データ` タブを読むことになる
- `掲載データ` は158行が式で常に存在する。**未面談の行は空文字で埋まる**ので、「行があること」を掲載対象の判定に使えない
- 公開判定の列名が `公開してよいか` → `公開可否`。選択肢の値は未設定（空欄）なので**まだ決まっていない**
- 年会費の表示文字列がシート側の式で出る。`lib/gender.ts` の `feeLabel()` と**二重実装**。どちらを正にするか
- 曜日が「チェックボックスの文字列」から「真偽値7列＋`曜日未確認`」に変わった。`active_days` への変換規則を書き換え
- 写真が「Drive URL を改行区切り」から「アイコン1列＋3列＋変換済みURL」に変わった。画像取得の入口が変わる

## 5. 「不定」と「未確認」について（①への追記）

`曜日未確認` 列で、**空欄と「決まっていない」は TRUE に寄せられる。**ここは解決している。

ただし c054 の「春学期は月水木　毎学期決めている　週３回」は、**「決まっていない」ではなく「学期ごとに決まる」**。チェックボックスで月水木が入り、`曜日未確認` は FALSE になる。**学期で変わることは、どこにも残らない。**

公開条件「全団体で活動日が埋まっている」と、この状態をどう扱うかは未定義のまま。

## 6. 決めたこと（2026/9/6）

| 論点 | 決定 |
|---|---|
| `division`（大分類） | **`団体マスタ` に列を足し、sync はマスタから引く。**フォームでは聞かない |
