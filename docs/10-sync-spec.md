# データ同期スクリプト 仕様

作成: 2026/08/30 ／ 東田
用途: **このファイルを Claude Code に渡して実装させる。**
やること: スプレッドシート ＋ Drive の写真 → `circles.json` ＋ 最適化済み画像

---

## 0. 設計方針（実装前に読む）

**スプレッドシートが唯一の原本。**生成された JSON と画像は、いつ消しても `npm run sync` で戻せる中間生成物として扱う。**JSONを手で直さない。**直すのは必ずシート側。ここを守らないと、どちらが正しいか分からなくなる。

**このスクリプトにAIを使わない。**158件を毎回モデルに通すと、同じ入力でも出力がブレるし、遅いし、金がかかる。変換は決定的な処理として書く。同じシートからは常に同じJSONが出ること。

（AIを使うのは1箇所だけ。**聞き取りメモから紹介文の下書きを作るところ**。これは `npm run draft` として**別コマンド**に分ける。同期処理に混ぜない。§8）

**冪等にする。**何度実行しても同じ結果。変化がなければ書き込まない（gitの差分を汚さない）。

---

## 1. 環境

- Node.js 20 以上、TypeScript
- シート取得: Google Sheets API v4（サービスアカウント）。シートはサービスアカウントに閲覧権限を付与する
- Drive取得: Google Drive API v3（同じサービスアカウント）
- 画像処理: `sharp`
- 認証情報は `.env`（`GOOGLE_SERVICE_ACCOUNT_JSON`, `SHEET_ID`, `SHEET_NAME`, `DRIVE_FOLDER_ID`）。**リポジトリに入れない**

---

## 2. コマンド

| コマンド | 動作 |
|---|---|
| `npm run sync` | 取得 → 検証 → 変換 → 書き出し → レポート |
| `npm run sync -- --dry-run` | 書き込まずレポートだけ出す。**警告の確認に使う** |
| `npm run sync -- --only=c001,c004` | 指定した団体だけ処理する |
| `npm run sync -- --force-images` | 画像キャッシュを無視して全部作り直す |

---

## 3. 出力

```
/data/circles.json          ← 公開対象の団体だけ
/data/report.md             ← 実行レポート（gitignore）
/public/photos/c001-1.webp  ← 幅1200
/public/photos/c001-1@600.webp
/public/photos/c001-2.webp
...
```

`circles.json` の形は `04-dummy-data.json` と**完全に同じ**にする。ダミーと本番を差し替えるだけで画面が動く状態を保つ。

`photos` は枚数（数値）ではなく**ファイル名の配列**に変更する。

```json
"photos": ["c001-1.webp", "c001-2.webp", "c001-3.webp"]
```

## 4. 公開判定 ★機械的に弾く

以下をすべて満たす行だけ `circles.json` に入れる。1つでも欠けたら**除外して、レポートに理由を出す。**

1. `公開してよいか` が `OK`
2. `団体ID` が `c###` 形式で、重複していない
3. `通称` と `正式名称` が空でない
4. `大分類` `公式の所属区分` が選択済み
5. `写真の掲載可否` が `不可` でない（`不可` の団体は写真なしとして通す。除外はしない）

**人間の記憶で管理しない。**「あの団体はまだ確認中だったはず」を頼りにすると、いつか事故る。

---

## 5. 検証（除外はしないが警告を出す）

`report.md` に一覧で出す。件数も出す。

- 所属人数 ≠ 男子＋女子（幽霊部員の数え方で普通に起きる。**止めない**）
- 初心者の人数 > 所属人数
- 活動曜日にチェックがあるのに活動時間が空
- 活動時間の形式が `HH:MM-HH:MM` でない
- 年会費が空欄（**未確認と0円の取り違えが一番起きやすい箇所**なので必ず出す）
- `年会費以外の費用` が `ある` なのに記述が空
- 次の新歓の日付が過去
- 写真が0枚
- 写真が9枚以上（**9枚目以降は無視する**）
- 紹介文が空、または3行未満
- キャッチコピーが20文字を超える（2行に収まらない）
- 取材日から**10か月以上経過**（次年度の更新対象）

## 6. 変換ルール

| シートの列 | JSONのキー | 変換 |
|---|---|---|
| 団体ID | `id` | そのまま |
| 通称 | `name` | 前後の空白を落とす |
| 正式名称 | `formal` | 同上 |
| 大分類 | `division` | そのまま |
| 公式の所属区分 | `category` | そのまま |
| ジャンル | `genre` | そのまま |
| 活動曜日 | `days` | チェックボックス → `[0..6]`（月=0）。「決まっていない」だけなら `[]` |
| 活動時間 | `schedule` | `18:00-20:00` → 全活動日に同じ値。`月 18:00-20:00 / 木 19:00-21:00` → 曜日ごとに割り当て。**パースできなければ `null` にして警告** |
| 活動場所 | `place` | 空欄 → `null` |
| 頻度 | `frequency` | 空欄 → `null` |
| 所属人数 | `members` | 数値。空欄 → `null` |
| 男子／女子の人数 | `gender` | `{male, female}`。**どちらか一方でも空欄なら `null`**（片方だけでは比率が出せない） |
| 初心者から始めた人数 | `beginners` | 数値。空欄 → `null` |
| 年会費 | `fee` | 数値。**空欄は `null`、`0` は `0`。ここを混同しない** |
| 年会費以外の費用 | `feeNote` | 記述あり → そのまま。20が `ない` → `"なし"`。20が `聞けなかった` → `null` |
| 掛け持ち | `dual` | `できる` / `できない` / 条件つきは条件文をそのまま |
| いま入れるか | `recruiting` | そのまま。空欄 → `null` |
| 次の新歓 日付・内容 | `welcome` | `{date, what}`。日付が空 → `null` |
| 紹介文 | `about` | 改行を `\n` で保持 |
| キャッチコピー | `catchcopy` | そのまま |
| 代表からの一言 | `leaderComment.text` | そのまま。**整形しない** |
| 面談相手の役職と学年 | `leaderComment.role` | `代表（3年）` の形。**個人名が入っていたら除去して警告** |
| SNS 3列 | `sns` | URL形式でなければ `null` にして警告 |
| 取材日 | `surveyedAt` | `YYYY-MM` に丸める |

**男女比を10の比率に丸めるのは、ここではやらない。**JSONには実数を入れて、画面側で丸める。データを比率で持つと、あとから人数に戻せない。

## 7. 画像処理

Drive の写真URLから元画像を取得して変換する。

1. Drive の fileId を抽出してダウンロード
2. **3:2 にクロップ**（`sharp` の `cover` ＋ 中央基準）
3. **幅1200（メイン）と幅600（一覧・先読み用）**の2枚を書き出す
4. WebP、品質82
5. ファイル名は `{団体ID}-{連番}.webp` / `{団体ID}-{連番}@600.webp`。**連番はシートの写真URLの並び順。**1枚目が一覧に出る
6. EXIF を落とす（**撮影場所の位置情報が入っていることがある**）
7. 最大8枚。9枚目以降は無視して警告

**キャッシュ**: 元ファイルの Drive `md5Checksum` を `/data/.image-cache.json` に保存し、変化がなければ再変換しない。`--force-images` で無視。

**注意**: Drive の直リンクを `<img src>` に使わない。重いし、共有設定の事故が起きる。必ずローカルに書き出したものを配信する。

## 8. 紹介文の下書き（別コマンド）

`npm run draft -- --id=c001`

聞き取りメモ（フォーム設問27）から、紹介文3〜5行の**下書き**を作って標準出力に出す。

- シートに**書き込まない。**出力を読んで、自分でシートに貼る
- 制約: 3〜5行 / 各行40字以内 / 「初心者歓迎」を使わない / キャッチコピーと同じ内容を繰り返さない / 誇張しない
- **メモにない事実を足させない。**足りない情報は `（要確認：合宿の有無）` の形で末尾に出す

同期処理に混ぜないこと。ビルドのたびに文章が変わるサイトになる。

## 9. レポートの形

```
=== sync 2026-09-14 18:20 ===
シート 43行 / 公開 31件 / 除外 12件

除外
  c007  公開してよいか = 確認中
  c012  写真の掲載可否 = 不可 ではないが 通称が空
  ...

警告
  c003  年会費が空欄（未確認か0円か要確認）
  c018  所属人数 31 ≠ 男16 + 女14
  c022  活動曜日にチェックがあるが活動時間が空
  c031  取材日から11か月経過（更新対象）

画像
  新規 8枚 / 更新 2枚 / キャッシュ 54枚 / 無視 1枚（9枚目以降）
```

**除外と警告を分けて出す。**除外は公開されない事故、警告は情報の質の問題で、対処の緊急度が違う。

## 10. 実装しないこと

- 管理画面。シートで足りる
- データベース。158件・更新は年1回・書き込むのは1人なので、JSONをリポジトリに置いてビルド時に読むほうが速く、安く、壊れない
- 団体側の編集機能。**公開して運用が回ってから考える。**いま作るとログイン・権限・監査が丸ごと増える
- 差分の自動コミット。`sync` は生成まで。コミットは自分でやる（何が変わったか見てから公開する）
