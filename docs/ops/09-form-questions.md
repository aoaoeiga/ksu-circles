# 掲載データ入力フォーム 設計 — 9/2版

作成: 2026/08/30 ／ 更新: 2026/09/09 ／ 東田
用途: 9/2版「京産大サークル名鑑 面談シート」の設問を記録する。既存35問の末尾に「代表からの一言」を戻し、全36問とする。

---

## 0. 大前提：これは団体に送るフォームではない

**面談中〜直後に、取材者がスマホで埋めるフォーム。団体には送らない。**

団体側に入力作業を発生させず、入力の手間をこちらで引き受けることがサービスの前提。写真は団体からDMで受け取り、DriveへのアップロードとURL入力は取材者が行う。

### 取材者と役職を取り違えない

`取材者` はフォームを入力する人、`面談相手の役職と学年` は話を聞いた相手の役職で、別の情報である。

**「面談相手の役職と学年」に取材者名や個人名を書かない。**この値は代表からの一言の署名に使う。`代表（3年）` `部長（2年）` の形にし、学年が聞けていなければ `代表` のように役職だけを書く。

syncでも個人名の可能性がある値は `代表` に置換して警告するが、置換に頼らず原本を直す。

---

## 1. 未確認の記録ルール

- 聞けなかった項目は、用意された `未確認` を選ぶか空欄のまま送信する。自由記述へ「わからない」と書かない
- 年会費は `年会費の状況` で無料・有料・未確認を分ける。無料は `無料（0円）`、未確認は `未確認`
- 男子割合は0〜100の数値で入れる。概数しか聞けなかった場合は空欄にする
- `活動曜日` の `決まっていない` と、単に聞けなかった空欄を混同しない

## 3. 3つのタブの役割

| タブ | 役割 |
|---|---|
| `回答` | フォーム36問の回答。フォームが書くので直接編集しない |
| `掲載データ` | `回答` からのVLOOKUP派生列＋手入力6列。syncが掲載本体として読む |
| `団体マスタ` | 団体ID・営業進捗・K列 `大分類`。syncは団体IDと大分類を読む |

`掲載データ` の手入力列は `紹介文` `キャッチコピー` `tile_size` `確認依頼日` `掲載OK日` `公開可否` の6つ。紹介文とキャッチコピーは面談中に完成させず、聞き取りメモを元に面談後に作る。

---

## 4. 面談後にやること

1. 聞き取りメモから紹介文とキャッチコピーを作り、`掲載データ` の手入力列へ入れる
2. `団体マスタ` K列の `大分類` が埋まっていることを確認する
3. 写真を手元で変換して `public/photos` へ置く。シートの写真URLは元ファイル探索用として残す
4. プレビューURLを団体へ送り、確認依頼日を記録する
5. OKが出たら掲載OK日と `公開可否 = OK` を記録する
6. `npm run sync` で生成し、差分を人が確認してからコミットする

`公開可否 = OK` でも紹介文かキャッチコピーが空なら、syncは確認中扱いにして公開せず警告する。
