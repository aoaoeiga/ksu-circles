# 掲載データ入力フォーム 設計

作成: 2026/08/30 ／ 東田
用途: **Googleフォームをこの通りに作る。**回答先スプレッドシートが掲載データの原本になる。

---

## 0. 大前提：これは団体に送るフォームではない

**面談中〜直後に、自分がスマホで埋めるためのフォーム。**団体には見せない。

理由。営業で「団体側に入力作業は発生しません」と言っているのが、このサービスの一番の武器になっている。フォームを送った瞬間にそれが嘘になる。**入力の手間をこちらが引き受けることが差別化そのもの**なので、ここは崩さない。

写真だけは団体からDMで送ってもらう。それも「インスタで使ってる写真を3〜5枚ください」で受け取り、**アップロードは自分がやる。**

---

## 1. 未確認の記録ルール ★最初に決めておく

**聞けなかった項目は空欄のまま送信する。**「わからない」と入力しない。空欄＝未確認として扱う。

例外が1つ。**年会費が0円の団体は `0` と入力する。**空欄にすると無料なのか未確認なのか区別がつかなくなる。サイト上でも `¥0` と `—` は別物として出す。

概数を実数として入れない。「だいたい半々」と言われた男女比は、**空欄**にする。

## 2. 設問一覧

セクションごとに分ける。**面談スクリプトと同じ順**に並べてあるので、上から順に埋まる。

### セクション1：管理

| # | 質問 | 形式 | 必須 |
|---|---|---|---|
| 1 | 団体ID | 記述式（`c001` 形式） | ✓ |
| 2 | 取材日 | 日付 | ✓ |
| 3 | 取材者 | 記述式 | ✓ |
| 4 | 面談相手の役職と学年 | 記述式（`代表（3年）`） | ✓ |

団体IDは**こちらで先に採番しておく。**大学公式の一覧を上から順に `c001`〜`c158` で振っておいて、面談前にIDを確認する。後から振ると重複する。

| # | 質問 | 形式 | 必須 |

**曜日は必ずチェックボックスにする。**自由記述にすると「月木」「月・木」「Mon,Thu」が混ざって、あとで正規化する羽目になる。

### セクション4：人数

| # | 質問 | 形式 | 必須 |
|---|---|---|---|
| 14 | 所属人数 | 数値 | |
| 15 | 男子の人数 | 数値 | |
| 16 | 女子の人数 | 数値 | |
| 17 | 初心者から始めた人数 | 数値 | |

**14と15+16が合わない場合がある**（幽霊部員の数え方が違う）。合わなくても入力を止めない。変換スクリプト側で警告だけ出す（`10-sync-spec.md` §5）。

男女は**比率ではなく人数で聞く。**「男女比は?」と聞くと「半々くらい」が返ってくるが、「男子と女子は何人ずつですか」と聞くと名簿を確認してくれる。

### セクション5：お金

| # | 質問 | 形式 | 必須 |
|---|---|---|---|
| 18 | 年会費（円） | 数値。**0円なら 0 と入力** | |
| 19 | 年会費以外にかかる費用 | 記述式（`合宿費 年1回 8000 / 道着 初回のみ 9000`） | |
| 20 | 年会費以外の費用はないか | ラジオ：ない／ある（19に記入）／聞けなかった | |

### セクション7：文章

| # | 質問 | 形式 | 必須 |
|---|---|---|---|
| 26 | 代表からの一言（そのまま載せる） | 段落 | |
| 27 | 聞き取りメモ | 段落。**面談中はここに雑に書く** | ✓ |
| 28 | キャッチコピー案 | 記述式 | |

**27がこのフォームで一番大事。**紹介文はここから作る。面談中に整った文章を書こうとすると手が止まって、相手の話が聞けなくなる。箇条書きでいい。

**26は相手の言葉のまま書き取る。**こちらで整えない。整えると全団体が同じ声になる。

29は掲載には使わないが、10団体ぶん集まるとサイトの項目を組み直す材料になる。

### セクション9：写真

| # | 質問 | 形式 | 必須 |
|---|---|---|---|
| 33 | 写真 | ファイルアップロード（画像・最大8枚） | |
| 34 | 写真の提供元 | ラジオ：団体から受領／こちらで撮影／未入手 | ✓ |

### セクション10：掲載確認フロー

| # | 質問 | 形式 | 必須 |
|---|---|---|---|
| 38 | 確認依頼を送った日 | 日付 | |
| 39 | 掲載OKが出た日 | 日付 | |
| 40 | 公開してよいか | ラジオ：OK／確認中／不可 | ✓ |

**40が `OK` の団体だけをビルドに含める。**これは変換スクリプト側で機械的に弾く（`10-sync-spec.md` §4）。人間の記憶で管理しない。

38〜40は面談時点では埋まらない。**フォームを送信したあと、スプレッドシートで直接更新する。**

---

## 3. 面談後にやること

1. 写真をDMで受け取ったら、Driveの該当フォルダにアップロード（フォームの再送信ではなく、シートの写真列を直接更新でもよい）
2. 27の聞き取りメモから紹介文3〜5行を作る（AIに下書きさせて、必ず自分で読む）
3. プレビューURLを団体に送って確認依頼 → 38に日付
4. OKが出たら 39と40を更新
5. `npm run sync` → コミット → 公開

---

## 4. スプレッドシート側で足す列

フォームの回答列のあとに、手で管理する列を足す。

| 列 | 用途 |
|---|---|
| `紹介文` | 27のメモから作った本文。3〜5行 |
| `キャッチコピー` | 28の案を推敲したもの |
| `写真URL` | Driveのファイル URL を改行区切り。最大8 |
| `除外理由` | ビルドから外している場合の理由 |
| `最終更新日` | 手で直したときに更新 |

**紹介文とキャッチコピーをフォーム側に置かない理由。**面談中に完成させる項目ではないので、フォームに入れると空欄のまま送信することになり、あとで「入れ忘れ」と区別がつかなくなる。**確定した文章はシートに書く**と決めておく。
