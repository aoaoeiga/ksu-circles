## 1. このページの仕事

京都産業大学の課外活動団体、約158団体をまとめた名鑑サイトの、**団体1つ分のページ**。

読者は2人いる。

**サークル代表（面談中・こちらのスマホを30秒覗き込む）★第一読者**
判断することは3つ。これは本物か。**うちの団体が載るとどう見えるか。**面倒なことをさせられないか。

**新入生（4月・スマホ・Instagramのリンクから流入・滞在3分）**
「一番いい団体」ではなく「失敗しない団体」を探している。

**成功条件**: 開いた瞬間に「おっ」と言われること。情報の網羅ではなく、**載ることが得に見えること**。

## 2. 大前提: ホームに合わせる ★最優先

**この画面は単体で成立させない。既に完成しているホーム画面と、同じサイトに見えることが最優先。**

以下は**ホームの実装から値を持ってきて、そのまま使う。**このファイルに書いてある数値と食い違ったら、**ホーム側を正とする。**

- 背景色・カード色・文字色・罫線色・アクセント色
- 角丸の大きさ
- 影の有無と強さ
- 書体と、見出し／本文／ラベルのサイズ
- ボタンの形（角丸かピルか、色、ラベルの書き方）
- ヘッダーの形と高さ

**この画面で新しく足してよいのは、§5 のヒーローの演出だけ。**ホーム側に手を入れるのも、§5-1 の遷移のために写真へ `view-transition-name` を付ける一点にとどめる。それ以外で新しい装飾・新しい色・新しい形を持ち込まない。「ホームにない要素は作らない」と考えてよい。

参考として、現状のトークンは以下（ホームと違っていたらホームを優先）。

| 名前 | 値 | 用途 |
|---|---|---|
| `paper` | `#FAFAF8` | 背景 |
| `ink` | `#16233C` | 主色。深い藍 |
| `ink-mid` | `#5A6478` | 補助テキスト、ラベル |
| `rule` | `#DFDFD8` | 罫線 |
| `match` | `#E8A33D` | 山吹。**「選んだ曜日と一致した」ときだけに使う。装飾に使わない** |
| `white` | `#FFFFFF` | カード面 |
| `scrim` | `#1B1A18` | **写真の上の暗幕とフッターにだけ使う。**新規追加 |

ジャンル色（写真がない団体のタイルにのみ使用。ホームで別の値を使っているならそちらを優先）

球技 `#2C6B58` ／ 武道 `#6E2E34` ／ 音楽 `#35387A` ／ 文化・創作 `#56487C` ／ ボランティア `#2B5678` ／ その他 `#454C5A`

## 3. 載せるもの・載せないもの

**載せない**（v3.0から削除した）

- 週の時間割セクション
- 「細かいこと」の明細リスト（場所・頻度・その他費用・掛け持ち・男女比を並べたもの）

情報を足すほど普通のサークル紹介ページに近づく。**このページは資料ではなく、1団体を見せる場所**にする。

**載せるもの**（この順序で固定）

1. 全画面の写真（またはジャンル色タイル）＋ 団体名
2. 一言紹介
3. 数字4つ
4. 紹介文
5. 次の新歓
6. SNS
7. フッター

### 3-1. 曜日の扱い ★確認したい点

活動曜日はセクションとしては削除するが、**1行だけ残すことを勧める。**

一覧で「月曜が空いている」で絞ってこのページに来た人にとって、曜日はここに来た理由そのもの。ページ内に一切ないと、絞り込みとページが繋がらなくなる。

なので、一言紹介のすぐ下に**セクション見出しなしの1行**として置く。

```
月・木  18:00–20:00        ← 等幅・14px・ink
```

グリッドにしない。見出しも付けない。**ただの1行**にする。フィルタ経由で来たときだけ、一致した曜日の文字を `match`（山吹）にする。

要らなければこの行ごと消してよい。その場合は §3 の順序から丸ごと抜く。

## 5. ヒーローの演出 ★この画面の主役

### 5-1. ホームから開いたとき ★演出の起点

**演出は個別ページで始まらない。ホームのカードを押した瞬間から始まる。**

1. 押されたカードの写真が、いまある位置とサイズのまま浮き上がる。ほかのカードと文字は120msで消える
2. その写真が**拡大しながら画面いっぱいに広がる。**440ms / `cubic-bezier(.2,.8,.2,1)`
3. 広がりきったところが、この個別ページのヒーロー

**ページが切り替わったのではなく、写真に寄っていったように見せる。**ここが今回の演出の要点。ホームで見えていた小さな写真と、いま見ている全画面の写真が、同じ1枚だと分かること。

実装は View Transitions API（写真に `view-transition-name` を付けて、一覧と個別ページで同じ名前にする）。非対応の環境では、200msのフェード → 全画面写真を `scale(1.04)` から `1.0` へ400ms、で代替する。

戻るときは逆再生。全画面の写真が、元のカードの位置とサイズへ縮んで戻る。

### 5-2. 入ったあとのズームイン

**縦画面いっぱい（100dvh）。**`vh` ではなく `dvh` を使う。スマホのアドレスバーで高さが変わると、下端の団体名が隠れる。

着地しても写真を止めない。**ゆっくり寄り続ける。**

| 時間 | 起きること |
|---|---|
| 0ms | 写真 `scale: 1.0`（§5-1の遷移から連続させる） |
| 0→6000ms | `scale: 1.0 → 1.06`（`cubic-bezier(.25,.1,.25,1)`）**寄る方向** |
| 300→900ms | 団体名が `opacity 0→1` ＋ `translateY(14px→0)` |
| 1400ms〜 | スクロール誘導が出る |

**6秒かけて6%だけ。**動いていると気づかないくらい遅くする。気づく速さにすると、落ち着かない画面になる。1.06に着いたらそこで止め、繰り返さない。

**必ず寄る方向（ズームイン）にすること。**引く方向だと、開いた直後に後退していく印象になって、§5-1で寄っていった動きと逆になる。

### 5-3. 指で拡大できるようにするか【任意・後回しでよい】

ヒーローの写真をピンチで拡大できるようにする案。入れる場合のルールだけ書いておく。

- **2本指のときだけ拡大。**1本指は常に縦スクロール。ここを混ぜると、スクロールしようとして写真が動く
- ダブルタップで等倍に戻す
- 拡大中はスクロールを止める

ただし**最初は入れなくていい。**面談で使う場面が思いつかないうちは、増やさない方がいい。

### 5-4. 上に乗せるもの

暗幕: `linear-gradient(to top, rgba(27,26,24,.82) 0%, rgba(27,26,24,.25) 45%, transparent 75%)`

**下から30dvhの範囲だけ**に文字を置く。上半分は写真だけにする。

- 区分・ジャンル: 11px / 字間 0.14em / `rgba(255,255,255,.75)`
- **団体名: 34px / 太 / 白**（このページで最大の文字）
- 正式名称: 13px / `rgba(255,255,255,.7)`

左右のパディングは20px、下端から40px空ける。

### 5-5. スクロール誘導

画面下端から20pxの位置、中央。細い `⌄`（1.5px線・幅18px）と、その上に `SCROLL`（10px・字間0.2em・`rgba(255,255,255,.6)`）。

1.8秒後にフェードイン。**8pxの上下運動を2.4秒周期で繰り返す。**スクロールが1pxでも始まったら即座にフェードアウトして、二度と出さない。

### 5-6. スクロールしたとき ★ここが要点

**写真は消えない。背後に残って沈む。**

- 写真は `position: sticky; top: 0`。画面に貼りついたまま
- シート（詳細）が下から上がってきて、写真の上に重なる
- シートが上がるにつれて、写真は `scale: 1.0 → 1.06`、`brightness: 1 → .55` に変化する。**シートの下に沈んでいく**表現
- シートは上端だけ角丸（**ホームのカードの角丸に合わせる**）。地色は `paper`
- シートの上端に、幅36px・高さ4pxの `rule` 色のつまみ（グラバー）を中央に置く。下から出てきたものだと分かる形にする
- シートが画面上端に着いたら、そこから先は普通のスクロール

**やらないこと**: 写真を上に流して消す（sticky にせず流すと、ただのページになる）。スクロール量を奪う（スクロールジャック）。速度を変える（スクロール1回分でシートが1画面分動く、素直な対応にする）。

### 5-7. 上部のナビ

最初は**何も出さない**。写真だけの画面にする。

シートが画面上端に達したタイミングで、上から高さ52pxのバーがスライドインする。中身は左に `⟨ 一覧`、中央に団体名（14px・1行・はみ出たら省略）。地色は `paper` に `rule` の下線1px、または**ホームのヘッダーと同じ形**。

戻るボタンは最初の画面にも要る。左上20pxの位置に、白い `⟨`（写真の上に直接。丸背景を敷かない。敷くと画面が濁る）。

### 5-8. 写真が2枚以上あるとき

ヒーロー内で横スワイプ。ドットインジケータは団体名の上、左揃え。**最大3枚。**

縦スクロールと競合するので、**横方向の判定を優先しすぎない。**斜めの動きは縦スクロールとして扱う。

### 5-9. 写真がない団体

**大半の団体に写真がない前提で設計する。**

全画面をジャンル色のベタ塗りにして、団体名を大きく組む。

- 写真のズームインの代わりに、**団体名が `scale 1.0 → 1.04` でゆっくり寄る**（同じ6秒）
- 団体名: 42px（写真ありのときより大きい）
- 「No Image」「準備中」と書かない。**欠落に見せない**
- スクロール時の沈み方は写真と同じ（`brightness .55`）

写真ゼロでも面談で見せられて、写真が集まるほど良くなる、という積み上がり方にする。

### 5-10. 動きを止める設定

`prefers-reduced-motion: reduce` のとき、**§5-1の拡大遷移・§5-2のズームイン・スクロール誘導の上下運動をすべて無効化**する。ホームからは普通のページ遷移にして、写真は最初から `scale: 1` `opacity: 1` で出す。シートは通常のページとして下に続く（sticky は残してよい）。

## 6. シートの中身

### 6-1. セクション見出し

**ホームの見出しの形をそのまま使う。**ホームが英字＋和文の二段になっているならそれに揃え、なっていないなら和文だけにする。

（二段にする場合の対応: `NUMBERS`＝数字で見る ／ `ABOUT`＝この団体について ／ `WELCOME`＝次の新歓）

### 6-2. 一言紹介

シートの一番上。カードに入れず地の上に直接。20px / 太 / `ink` / 2行まで。

**ここがページで2番目に大きい文字。**事務的な説明を書かない（§8）。

### 6-3. 数字4つ

2×2。1枚の中身は上から、数値（等幅・28px・`ink`）、ラベル（11px・字間0.14em・`ink-mid`）。

`¥3,000` 年会費 ／ `42` 所属人数 ／ `12` うち1年生 ／ `28` 初心者出身

**4枚に固定する。増やさない。**この4つが大学公式サイトに一切載っていない数字で、このサイトの存在理由そのもの。

未確認の項目は、数値の位置に `未確認`（16px・`ink-mid`）と入れる。**カードごと消さない。**空いているカードが、聞き取りが済んでいないことを示す。

`¥0` は無料。`未確認` とは別物として必ず区別する。年会費が未入力の団体を無表示にすると、無料に見える。

### 6-4. 紹介文

3〜5行。15px / `line-height 1.85`。段落間は12px。

### 6-5. 次の新歓

日付を等幅22pxで `2026.10.02` の形。その下に内容を14px。下にボタン（**ホームのボタンと同じ形**）。

予定がないときはボタンを出さず、`未定` と `決まりしだい、このページに載せます。` を出す。

### 6-6. SNS

Instagram / X / 公式サイト の3つを横並び。持っていないものは押せない状態で残す（消さない）。

### 6-7. フッター

`scrim` 地・白文字。ページで唯一の暗い面。

- `掲載内容は運営が団体に聞き取って作成し、公開前に団体へ確認しています。`
- `情報の修正・取り下げはこちら`（下線・12px）

## 7. 未確認データ

**空欄を空欄のまま出さない。**必ず `未確認` と `ink-mid` で書く。

未確認が多い団体でもレイアウトが崩れないこと。カードや行を消して詰めない。**未確認の量がそのまま「まだ聞けていない量」として見える**のが正しい状態。面談中の代表に「ここを埋めさせてください」と言える。

---

## 8. 文言

- **「初心者歓迎」と書かない。**全団体が歓迎を名乗るので情報がない。実数（`28人が初心者スタート`）を出す
- 一言紹介は団体の**制約**を書く。「楽しいサークルです」ではなく「週1回、来られる日だけ来ればいい」
- ボタンは起きることをそのまま書く。`送信` ではなく `詳しく見る`
- 空の状態は説明で終わらせず次を書く。`未定` の下に `決まりしだい、このページに載せます。`

## 9. 完成の判定

1. **ホーム画面と並べて、同じサイトに見えるか**（色・角丸・影・書体・ボタンの形）
2. ホームのカードを押したとき、**その写真が拡大して全画面になるか**（ページが切り替わったように見えていないか）
3. 着地後のズームが**寄る方向**で、6秒かけて気づかない速さで動いているか
4. スクロールすると、写真が消えずに背後に沈んでシートが上がってくるか
5. 写真がない団体（`c02` `c03` `c05`）が、写真がある団体と同じくらい良く見えるか
6. 未確認が多い団体（`c03`）でレイアウトが崩れていないか
7. `¥0` と `未確認` が明確に別物として見えるか
8. 山吹が「一致」以外の場所に1箇所も使われていないか
9. 暗い面がフッターと写真の暗幕以外に出ていないか
10. 375px幅で横スクロールが発生しないか
11. アドレスバーの出入りで団体名が隠れないか（`dvh` を使っているか）
12. `prefers-reduced-motion: reduce` でズームとフェードが止まるか
13. **代表に30秒見せたとき、最初に目が行くのが写真と団体名になっているか**
