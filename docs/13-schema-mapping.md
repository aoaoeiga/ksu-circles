# スキーマ対応表 — Design ↔ 本番

作成: 2026/08/30
なぜ要るか: **Claude Design のコードに直書きされているダミーデータと、フォームから集めるデータの形が違う。**移植のときにここを揃える。

---

## 1. そのまま使うフィールド

Design のコードが使っている名前をそのまま本番の型にした。**UI側の書き換えを最小にするため。**`d.member_count` のような参照が全部そのまま動く。

`id` `short_name` `name` `category` `genre` `one_liner` `active_days` `frequency_per_week` `hours_per_session` `place` `annual_fee` `extra_cost_note` `member_count` `beginner_count` `first_year_count` `multi_club_ok` `description` `place` `sns` `photos` `tile_size`

---

## 2. 変えるフィールド

| Design | 本番 | 理由 |
|---|---|---|
| `gender_ratio: "6:4"`（文字列） | `gender: { male, female }`（実数） | 丸め済みの文字列で持つと、あとから人数に戻せない。**丸めは表示時に `lib/gender.ts` の `genderRatio()` で行う** |
| `next_recruit: "4月上旬（後期からの…）"`（自由文） | `recruiting`（バッジ）＋ `next_recruit: { date, what }` | 「いま入れるか」と「次の新歓の日程」は別の情報。日程が無くても状態は出せる |
| `real: true` | 削除 | 公開判定は sync 側が `公開してよいか = OK` で機械的に行う。データに持たせない |

---

## 3. 足すフィールド

Design のダミーには無いが、フォームでは既に集めている。

| 本番 | 中身 | フォームの設問 |
|---|---|---|
| `division` | 運動系 / 文化系 / その他 | 「大分類」 |
| `active_times` | `{ "0": ["18:00","20:00"] }` | 「活動時間」をパースする |
| `leader_comment` | `{ text, role }` | 「代表からの一言」「面談相手の役職と学年」 |
| `surveyed_at` | `"2026-09"` | 「取材日」を月に丸める |
| `recruiting` | いつでも入れる / 4月のみ / 募集していない | 「いま入れるか」 |

**Design 側では代表からの一言が `detail.voice` で、署名が `代表（3年）` の直書きになっている。**ここをデータから読む形に直す。

---

## 4. スプレッドシートに1列足す ★これだけ足りない

| 列名 | 値 | 既定 |
|---|---|---|
| `tile_size` | `S` / `M` / `L` | `M` |

一覧のタイルの大きさ。Design の一覧は大きさの違うタイルを混ぜて並べる作りになっていて、この値で決まる。フォームの設問には無いので、**シートに手で足す列**として扱う。

決め方の目安。

- `L` — 写真が良い、目立たせたい団体。**全体の1〜2割まで**
- `M` — 既定
- `S` — 写真がない団体、情報が少ない団体

写真の枚数から自動で決めてもいいが、**全部Lになると一覧が単調になる**ので、手で決める余地を残しておく。

## 5. 未確認の扱い（再掲・ここが崩れやすい）

- `annual_fee` … `0` は無料、`null` は未確認。**混同すると未確認が無料に見える**
- `extra_cost_note` … `"なし"` は確認済みで無い、`null` は聞けていない
- `gender` … 男女どちらか一方でも空欄なら `null`（片方だけでは比率が出せない）
- `active_days` … 空配列で「活動日 未確認」。**30pxのまま大きく出す**
- 数字カードの中は `—`、カードの外は文字で `未確認`
