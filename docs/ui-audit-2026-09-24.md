対象: 本番 https://ksu-circles.vercel.app（main `95e4dcd` 時点）の一覧と、6団体すべての団体ページ
目的: 狙っているデザインとのずれと、新入生が使うときに引っかかる点を洗い出し、直す順番を決める
**このレポートではコードを変えていない。**スクリーンショットは `docs/ui-audit-2026-09-24/` にある。

## 1. 狙いとのずれ

### A1. 背景が白ではなく灰色

- **どこで:** 全ページ
- **何が:** 背景は `#EFEFEB`（`lib/design.ts` の `BG`）。
  - `docs/ui/06-design-reference.md` の §3 で、「白いカードとの差を出すために地を落とした」と決めた値です。
- **スクショ:** `ui-audit-2026-09-24/m-home-01-top.jpg`, `pc-home-01-top.jpg`
- **直し方の案:**
  - 背景を白にするなら、今ある「地と白カードの差」で分けている箇所に、代わりの区切りが要ります。対象は、活動日カード・数字カード・紹介文のカードです。
  - 案は2つです。罫線 `rule` で区切るか、カードの地を薄いグレーにして反転させるか。
  - 決める前に、`docs/ui/06` と CLAUDE.md の「スタイルは Claude Design から持ち込んだものをそのまま使う」を改めることが要ります（§9 参照）。

### A2. 写真タイルが角丸の長方形（多角形ではない）

- **どこで:** 一覧のタイル（`.circle-tile`、`border-radius: 16px`）
- **何が:** 角を切り落とした形になっていない。
  - 詳細への遷移（`lib/flip.ts`）も、角丸16px のまま広がる前提で作られています（`TILE_RADIUS = 16`）。
- **スクショ:** `m-home-03-grid.jpg`
- **直し方の案:**
  - `.circle-tile` に `clip-path: polygon(...)` で角を切ります。例えば右上と左下を 14px 落とします。
  - 遷移は、`flip.ts` で角丸を補間している部分を、`clip-path` の補間に置き換えます。
  - 影武者のタイル（戻り）にも同じ `clip-path` を当てます。

### A3. 「表紙（不揃い）」と「一覧（そろえる）」が分かれていない

- **どこで:** 一覧
- **何が:**
  - グリッドは1つだけで、タイルの大きさは団体IDを3で割った余りから決まっています（square / wide / large、`lib/tile-layout.ts`）。
  - 大きさに意味がないので、比べるための一覧としては大きさがばらつき、表紙としては写真の良し悪しと関係なく大きいタイルが決まります。
  - 例: c054 は ID の都合で大きい（L）が、c055 は小さい正方形で、集合写真の人が豆粒になる。
- **スクショ:** `m-home-03-grid.jpg`, `m-home-04-grid2.jpg`, `pc-home-03-grid.jpg`
- **直し方の案:**
  - 冒頭に「表紙」を作ります。写真の良い団体を最大5件、不揃いのベントーで並べます。どの団体を載せるかは、シートの `tile_size = L` で運営が選びます。
  - その下の「一覧」は、全団体を同じ形（3:2）・同じ大きさの2列にそろえます。
  - `tileShapeForId` は一覧では使わなくなります。

### A4. 写真は普段から暗いが、タップしても明るくならない

- **どこで:** 一覧のタイル（`PhotoTile.tsx`）
- **何が:**
  - 普段は `filter: brightness(0.86)` に、下55%の暗幕を重ねています。
  - PC のホバーでは明るくなります（`pc-hover-before-after.jpg`）。
  - スマホには `:active` の指定がないので、押した瞬間の変化がありません。
- **スクショ:** `pc-hover-before-after.jpg`
- **直し方の案:** `.circle-tile:active [data-photo]` と `:focus-visible` にも、ホバーと同じ `filter: brightness(1)` を当てます。
  - iOS で `:active` を効かせるには、`<body ontouchstart="">` か、タイルに `onTouchStart` の空関数が要ります。

### A5. アニメーションが4か所に収まっていない

- **狙い:** 動くのは、ロード・スクロール・ホバー・フィルタ適用の4か所だけ（タイル→詳細の拡大は別枠として狙いに入っている）。
- **今あるもの**（`app/globals.css` の keyframes と各部品から数えた）:

| 場所 | 動き | 狙いの4か所に入るか |
|---|---|---|
| 一覧の見出し | 3行が順に下から（`lineUp`） | ロード ○ |
| 一覧のタイル | 画面に入ると現れる（IntersectionObserver） | スクロール ○ |
| 一覧のタイル | ホバーで明るく | ホバー ○ |
| 一覧 | 絞り込みで並び替え（FLIP） | フィルタ ○ |
| タイル→詳細 | 位置から広がる／戻りで縮む（`lib/flip.ts`） | 狙いの別枠 ○ |
| 詳細のヒーロー | 開いたあと、さらにズームイン（`heroZoomIn`） | × |
| 詳細のヒーロー | 写真がゆっくり寄り続ける（`slideZoom`） | × |
| 詳細のヒーロー | 写真の自動送りと、進捗バー（`dotFill`） | × |
| 詳細のヒーロー | SCROLL の矢印が上下に揺れる（`cueBob`） | × |
| 詳細 | 中身のフェード（`DETAIL_REVEAL_TRANSITION`）・シートの立ち上がり | スクロール △ |

- **スクショ:** `m-flip-open-strip.jpg`
- **直し方の案:**
  - × の4つを外します。自動送りは手動スワイプだけにし、進捗バーは「今何枚目か」の静止した点にします。
  - `docs/ui/08-carousel.md` の自動送りの仕様も、合わせて改めます。

### A6. 曜日の「一致」が、狙いの形になっていない

- **どこで:** 一覧（絞り込み後）と、詳細の活動日カード
- **何が:**
  - 一覧のタイルには曜日がありません。水曜で絞り込んでも、残ったタイルに「なぜ残ったか」が出ません（`m-filter-03-wed-list.jpg`）。
  - 詳細の活動日カードは、活動する曜日だけを「月・水・木」の文字で並べています。
    - 一致した曜日は山吹 `#E8A33D` で、順にずれて染まる動きはありません。7マスのセルもありません（`m-filter-04-wed-detail-daycard.jpg`）。
  - 山吹は、白いカードの上だとコントラストが 2.16:1 で、大きい文字の基準（3:1）にも届きません。
- **直し方の案:**
  - 一覧のタイルと詳細の両方に「月〜日の7マス」を置き、活動日をマスの塗りで示します。
  - 絞り込み中は、選んだ曜日と一致したマスだけを朱 `#E8442B` で、左から 40ms ずつずらして染めます。
  - 実装の中身は §10 の上位3 を参照。
  - **CLAUDE.md §5（一致は山吹）を改める必要があります**（§9）。

### A7. 小さい欧文ラベルが残っている

- **どこで:**
  - 詳細のヒーローにある `SCROLL`（10px、字間 2px、白60%）
  - 大きな英字の見出し `CIRCLES` `NUMBERS` `ABOUT` `VOICE` `JOIN`（32px）と、その上に字間を広げて置いた11px の和文のラベル
- **スクショ:** `m-c056-01-hero.jpg`, `m-all-02-daycard.jpg`
- **何が:**
  - `SCROLL` は、狙いの「小さい欧文ラベル」そのものです。
  - 英字の見出しは小さくはありませんが、`docs/ui/06` §1 が「英字が見出し、和文が意味」と決めた文法です。
- **直し方の案:**
  - `SCROLL` は消し、矢印だけにするか、何も置かないようにします（B3 と合わせて）。
  - 英字の見出しは、和文の見出し（「数字で見る」など）を主役にして英字を消すか、残すかを決めてから直します（§9）。

### A8. タイル→詳細の遷移で、フレームが飛ぶ

- **どこで:** 一覧の c056 をタップ → 詳細 → 戻る
- **何が:** `requestAnimationFrame` の間隔を実測しました（60fps なら 16.7ms）。
  - 開くとき: 中央値 16.7ms、95%値 **150ms**、最大 **167ms**、33ms を超えた回数 8
  - 戻るとき: 中央値 16.7ms、95%値 50ms、最大 **150ms**、33ms を超えた回数 6
  - 拡大・縮小は 380ms なので、その間に 150ms 級の止まりが入ると、1〜2コマ飛んで見えます。
  - ヘッドレスでの計測なので、実機では小さくなる可能性があります。
- **スクショ:** `m-flip-open-strip.jpg`, `m-flip-back-strip.jpg`
- **直し方の案:**
  - 遷移中に重い仕事が重なっています。1600px の写真のデコードと、`heroZoomIn` などヒーローの演出です。
  - F2（画像を小さくする）と A5（演出を減らす）で、まず減るはずです。
  - 残るようなら、拡大は `width/height` ではなく `transform` と `clip-path` で動かし、画像のデコードは `img.decode()` を待ってから始めます。

## 2. 新入生がスマホで初めて開いたとき

### B1. 見出しが「全部ここに。」なのに、6団体しかない

- **どこで:** 一覧の最初の画面
- **何が:** すぐ下に「6団体を、活動曜日と年会費から探せます。」とあります。約158団体の名鑑として開いた人には、「全部」と「6」がちぐはぐに見えます。
- **スクショ:** `m-home-01-top.jpg`
- **直し方の案:** 掲載数が少ないうちは、「京産大のサークルを、同じ項目で比べる。」のように数を約束しない見出しにします。
  - 小見出しは「いま6団体。順次追加中」のように、今の数を正直に出します。

### B2. タイルに名前しかなく、比べられない

- **どこで:** 一覧
- **何が:** キャッチコピーが出るのは大きいタイル（c054）だけで、他は名前だけです。ジャンル・曜日・年会費が見えないので、比べるには1件ずつ開く必要があります。
- **スクショ:** `m-home-03-grid.jpg`
- **直し方の案:** 一覧のタイル（A3 でそろえた形）に、名前の下へ1行で「曜日7マス・年会費」を置きます。
  - 掲載項目は増やさず、今ある `active_days` と `annual_fee` を表に出すだけです。

### B3. 詳細の1画面目が写真だけで、情報を読むにはスクロールが要る

- **どこで:** 団体ページのヒーロー
- **何が:** 1画面目は全画面の写真と団体名だけです。スクロールの合図は 10px の `SCROLL` で、明るい写真の上ではコントラストが 1.6:1 しかありません。
  - `docs/ui/06` の「1画面目で情報を見せない」は意図した方針ですが、第二読者の新入生は迷います。
- **スクショ:** `m-all-01-hero.jpg`
- **直し方の案:** ヒーローの高さを 100svh から 72svh 前後に下げ、画面の下にキャッチコピーと活動日の7マスがのぞくようにします。
  - 方針の変更なので、§9 で決めてから直します。

### B4. 戻る操作が小さく、文字がない

- **どこで:** ヒーローの左上の「⟨」（34×44px、見た目は文字1つ）と、スクロール後に出るバーの「⟨ 一覧」
- **スクショ:** `m-c056-01-hero.jpg`, `m-c056-02-sheet.jpg`
- **直し方の案:** 44×44 以上にし、写真の上では半透明の丸い下地を付けて「⟨ 一覧」と文字も出します。

### B5. 「情報の修正・取り下げはこちら」が押しても何も起きない

- **どこで:** 全団体ページのフッター
- **何が:** `href="#"` のままです（`app/c/[id]/page.tsx`）。団体の代表が一番探すリンクなので、困ります。
- **スクショ:** `m-c056-04-full.jpg`
- **直し方の案:** 修正・取り下げのフォームの URL を入れます（URL は運営が決める）。
  - 決まるまでは、リンクではなく「修正・取り下げは運営の Instagram の DM へ」のような文にします。

### B6. ヒーローの分類と団体名の表示が重なる・崩れる

- **どこで:** 団体ページのヒーロー
- **何が:**
  - 分類の行が「その他 ・ 委員会・その他」（c056）、「その他 ・ 学生プロジェクトチーム」（c058）のように、大分類と区分をそのままつないでいて、「その他」が重なります。
  - 通称と正式名称が同じ団体は、同じ名前が2回出ます（「京産大起業部 / 京産大起業部」「BRE＋ND / BRE＋ND」）。
  - c014 の正式名称が「届出団体神山ポケモンサークル」で、区分がくっついています（データの問題）。
- **スクショ:** `m-all-01-hero.jpg`
- **直し方の案:**
  - `lib/labels.ts` の `divisionText` で、大分類が「その他」のときは区分だけを出します。
  - 正式名称が通称と同じときは、正式名称の行を出しません。
  - c014 の正式名称はシートで直します。

## 3. 写真まわり

### C1. 詳細のヒーローで、横長の写真の7割が切れる

- **どこで:** 団体ページのヒーロー（スマホ）
- **何が:** 3:2 の写真を、縦長の全画面（約 390×844）に `object-fit: cover` で出しています。**横幅の約31%しか見えません。**
  - c054 は、一覧では3人が走っている写真が、詳細では1人だけになります。
  - c055 は集合写真の両端が切れます。
- **スクショ:** `m-all-01-hero.jpg`（一覧の `m-home-03-grid.jpg` と見比べる）
- **直し方の案:** 上位5 を参照（§10）。

### C2. 一覧のタイルでも、形によって写真の切れ方が変わる

- **どこで:** 一覧
- **何が:**
  - wide のタイル（350×170、約2.06:1）では、3:2 の写真の上下が切れます。
  - 正方形（170×170）では左右が切れ、集合写真の人が小さくなります。
  - 切り抜く位置は中央で固定です（`object-position: 50% 50%`）。
- **スクショ:** `m-home-03-grid.jpg`
- **直し方の案:** A3 で一覧のタイルを 3:2 にそろえれば、切れはなくなります。
  - 表紙の不揃いのタイルだけは切れるので、写真ごとの見せたい位置をシートかマニフェストに持たせ、`object-position` に使います。

### C3. 写真の枚数が1〜5枚とばらつく

| 団体 | 枚数 | 備考 |
|---|---|---|
| c055 | 1 | カルーセルなし |
| c014 | 2 | 01・03（02 は欠番） |
| c058 | 3 | |
| c056 | 4 | |
| c047 | 5 | |
| c054 | 5 | |

- **何が:** 1枚でも崩れてはいません。ただ、2枚の団体では、ページ送りの点が2つだけの薄い見た目になります。
  - ページ送りの点は、タップできる範囲が 20×44px です（G2）。
- **直し方の案:**
  - 1〜2枚の団体は、ページ送りの点を出さないようにします。
  - 掲載の目安として「3枚以上」をフォームに書きます（運用）。

### C4. 写真の明るさがそろっていない

- **何が:** 各団体の 01 の平均輝度は、**94〜147** とばらついています（c054 94、c056 100、c058 109、c014 119、c047 124、c055 147）。
  - 一覧では一律に ×0.86 をかけるので、差はそのまま残ります（81〜126）。
  - 処理の経路が2つあります。Drive から取り込む写真はガンマ補正（上限 ×1.15）がかかり、手元で処理した zip の写真（c014・c047・c054）は補正なしです。基準が1つになっていません。
- **スクショ:** `m-home-03-grid.jpg`
- **直し方の案:**
  - 手元で処理した写真も `scripts/photos.ts` の同じ処理に通します（`.manifest.json` の `local` の分を、sync が再処理できるようにする）。
  - 一覧の暗さは、一律の倍率ではなく「平均輝度が目標になるよう」写真ごとに決めた値を `circles.json` に持たせます。

## 4. 文字

### D1. 紹介文の途中の改行が、段落の区切りとして出る

- **どこで:** c054 の紹介文
- **何が:** シートで「活動する曜日は」「毎学期メンバーの…」と途中で改行してあり、画面では1行ずつが別の段落（間 12px）になっています。文の途中で段落が切れて見えます。
- **スクショ:** `m-c054-03-about.jpg`
- **直し方の案:** 画面側では空行（`\n\n`）だけを段落の区切りにし、1つの改行はつなげて流します（`app/c/[id]/page.tsx` の `description.split("\n")` の部分）。
  - あわせて sync に、「行が句点以外で終わっている」という警告を足します。

### D2. 代表からの一言が、フォームの原文のまま出ている

- **どこで:** c047 の VOICE
- **何が:** 「十を作りdして１００で伝える」「プレ件の人に声かけて」など、聞き取りの打ち間違いがそのまま出ています。
- **スクショ:** `m-c047-03-about.jpg`
- **直し方の案:** シート側で直します（原文は団体の言葉なので、運営が直してよい範囲を団体に確認する）。
  - sync に「半角と全角の数字が混ざる」「ひらがな1字のあとに英字」などの簡単な検査を足すことも考えられます。

### D3. 活動場所が聞き取りの誤変換のまま

- **どこで:** c047 の活動日カード「活動場所 サギたりウスカン」
- **スクショ:** `m-filter-04-wed-detail-daycard.jpg`
- **直し方の案:** シートで正しい建物名に直します。

### D4. ヒーローの団体名が、語の途中で折り返す

- **どこで:** c014 のヒーロー「神山ポケモンサー／クル」
- **スクショ:** `m-c014-01-hero.jpg`

### 上位5件の実装メモ

#### 1. 画像を表示サイズに合わせる（F2・F3）

**ゴール**

- 一覧の画像の転送量: 1,418KB → **300KB 以下**
- 一覧の LCP: 11.7秒 → **4秒以下**（Lighthouse モバイル）
- c056 の転送量: 2,196KB → **1,000KB 以下**

**sync 側**（`scripts/photos.ts`）

- `processImage` で、今の幅1600の版に加えて、同じ処理の結果を幅1200 `@1200.webp` と幅600 `@600.webp` にも書き出します。3:2 のまま、拡大はしません。
- `PROCESS_VERSION` を 5 に上げます。
- 手元コピー（`local`）の団体は、今のファイルから同じ2サイズを作ります（`sync` の中で、`local` の写真を `sharp` で縮めるだけ）。
- CLAUDE.md の「幅1200と600に変換済み」という記述と一致するようになります。

**データ**（`types/circle.ts`）

- 形は変えません。`photos` は今のパス（`/circles/c056/01.webp`）のまま。
- 表示側で `@600` `@1200` を組み立てます。

**表示側**

- `lib/design.ts` の `photoSrc` を、`/circles/…` にも `@600` を返すよう直し、`photoSrcSet(file)` を足します（`"…@600.webp 600w, …@1200.webp 1200w, ….webp 1600w"`）。
- `components/PhotoTile.tsx` の `<img>` に `srcSet` と `sizes` を付けます。`sizes` は `(min-width:768px) 25vw, 50vw`。large と wide のタイルは `(min-width:768px) 50vw, 100vw`。
- `components/HomeScreen.tsx` で、表示順の先頭2枚だけを `priority` にします（`loading="eager"` と `fetchPriority="high"`）。
- `components/Hero.tsx` のヒーローの `<img>` にも `srcSet` を付け、`sizes="100vw"` にします。

**確認**

- `npm run build` のあと、このレポートの §0 と同じ手順で Lighthouse を回します（一覧と c056）。
- 一覧の画像の転送量は、§0 と同じ方法（ページが読んだ画像の合計）で数えます。

#### 2. フォントの描画ブロックを外す（F1）

**ゴール**

- Lighthouse の「描画を止めるリソース」の指摘を0にする
- FCP を全ページで **2.5秒以下**にする

**実装**（`app/layout.tsx`）

- Google Fonts の `<link>` をやめ、`next/font/google` で同じ4ファミリ・同じ太さを読みます。
  - Zen Kaku Gothic New 500/700
  - Noto Sans JP 400/500
  - Schibsted Grotesk 700
  - Outfit 400/500/600
  - 日本語の2つは `preload: false`、欧文の2つは `preload: true` にします。`display: "swap"`。
- 各フォントに `variable: "--font-zen"` などの CSS 変数を付け、`<html className=...>` に並べます。

**書体名の置き換え**

- inline style の書体名（`'Zen Kaku Gothic New',sans-serif` など）は、`lib/design.ts` に `FONT_ZEN = "var(--font-zen), sans-serif"` などの定数を作り、そこから参照します。
- 置き換えは機械的にできます（`grep -rn "'Zen Kaku Gothic New'" components app lib` で出る箇所）。
- 書体・太さ・大きさは変えないので、見た目は同じです。
- `app/layout.tsx` の「next/font に替えると font-family 名が変わる」というコメントの懸念は、CSS 変数で吸収します。

**確認**

- スクショ（`m-home-01-top.jpg` と同じ位置）を撮り直し、文字の見た目が変わっていないことを重ねて確かめます。
- Lighthouse を回します。

#### 3. 曜日7マスと、一致を朱で順に染める（A6・B2）

**前提:** §9 で CLAUDE.md §5 の一致色を朱 `#E8442B` に改めること。

**部品**（新規 `components/DayRow.tsx`）

- `active_days` と「選んだ曜日」を受け取り、月〜日の7マスを横に並べます。
  - 活動日: `ink` の塗りに白の文字
  - 活動しない日: `rule` の枠
  - 未確認（`active_days` が空で `days_undecided` が false）: 7マスとも点線の枠に「—」
  - 不定期（`days_undecided` が true）: 7マスをつないだ帯に「曜日は決まっていない」
- 一致したマスは、朱の塗りに白の文字（14px の太字以上）にします。
- 絞り込みを反映した瞬間に `transition: background-color 180ms` と `transition-delay: calc(var(--i) * 40ms)` で、左から順に染めます。`--i` はマスの番号 0〜6 です。

**置き場所**

- 一覧のタイル: 名前の下（A3 の前なら、全タイルの下端に 20px の帯として重ねる）
- 詳細の活動日カード: `components/DayCard.tsx` の「月・水・木」の文字を、この7マスに置き換えます。

**色の定数:** `lib/design.ts` の `MATCH` を `#E8442B` にし、CLAUDE.md §5 の本文も同時に直します。

**確認**

- `/?days=2` と `/c/c047?days=2` で、水だけが朱になることを見ます。
- 1枚目と4枚目のマスのスクショを 200ms ごとに撮り、ずれて染まることを確かめます。

#### 4. 操作できる範囲とキーボード（E2・G2・G3・B4）

**チップ**（`components/HomeScreen.tsx` の曜日・区分・ジャンル・年会費）

**ヒーロー**（`components/Hero.tsx`）

- 戻る「⟨」: 44×44 以上にし、`background: rgba(0,0,0,.28); border-radius: 999px` の下地と、「一覧」の文字を付けます。

**フッターのリンク:** `display: inline-block; padding: 14px 0` で高さを 44px 以上にします（リンク先は B5）。

**確認**

- Tab キーだけで、絞り込み → 曜日を選ぶ → 表示 まで操作できることを確かめます。

#### 5. 詳細のヒーローで写真が切れすぎるのを直す（C1）

**ゴール:** スマホのヒーローで、3:2 の写真の横幅が **100% 見える**こと。

**実装**（`components/Hero.tsx`、`app/globals.css`）

- ヒーローの1枚ごとに、同じ写真を2枚重ねます。
  - 背面: 今と同じ全画面の `object-fit: cover` に、`filter: blur(24px) brightness(.6)` をかけ、`transform: scale(1.1)` で縁のぼけを隠します。
